# DSH 插件界面设计与验收规范

适用对象：为 DSH 实现或修改插件界面的开发 Agent 与维护者。目标是让插件使用宿主的视觉和交互习惯，并让文字、状态和操作始终清楚可辨。

这是本仓库的开发约定，可复制到其他 DSH 插件；不是 DSH 官方 API 声明。下文的主题变量和基础尺寸核对自 **DSH 0.2.1-rc.5**，日期为 **2026-11-06**。DSH 升级后先核对宿主再更新规范，不能把旧截图或旧变量值当成永久标准。

## 1 给开发 Agent 的执行要求

修改界面前，按顺序完成以下工作，不需要为常规样式选择额外请求审批：

1. 确认目标界面属于设置页、浮层、输入框工具条还是组件详情，找到 DSH 中对应的原生界面。
2. 读取当前运行时的主题和基础控件实现，确认变量、尺寸、组件导出和加载能力；不要从颜色名称或截图猜实现。
3. 确定主要操作、信息顺序和需要覆盖的状态，再复用现有样式或修改唯一的公共规则。
4. 在真实主题下验证浅色、深色、窄窗口和长内容；检查文字对比度、键盘操作和原有业务行为。
5. 在 PR 中提交验证证据及未验证项。隔离渲染通过与真实 DSH 验收通过分别记录。

当前仓库的入口是 [client.js](../client.js)，界面回归测试是 [test/client.test.js](../test/client.test.js)。[design-v1.2.md](design-v1.2.md) 是历史产品方案；新界面以本规范为准，当前功能行为以代码和 README 为准。

原生依据的定位方法：

| 要核对的内容 | 当前运行时中的来源 | 使用方式 |
|---|---|---|
| 主题颜色、字体、圆角 | `@deepseek-ai/dsh-client-ui-theme` 的 `package.json`、`lib/client.js` | 核对包版本、主题变量与基础样式 |
| 按钮、标签、输入控件 | 当前 DSH 的 `ui-primitives` 源码或 `dsh-web-frontend/dist/assets/*.css` | 检查实际尺寸、状态和变量，不依赖构建后的散列类名 |
| 设置行与页面留白 | DSH 原生通用设置页及其实现 | 对照相同类型控件，不拿聊天气泡作设置页模板 |
| 插槽与客户端依赖 | 当前 DSH 暴露的插件契约及本插件加载声明 | 确认能力存在后使用，不猜测 import 路径 |

宿主公开且可加载的基础控件优先复用。不能加载时，用原生 HTML/React 元素配宿主变量实现同等行为。当前插件是单文件客户端、无 JSX、仅 `require('react')`；不能直接加入一个未验证可加载的私有 UI 包。

## 2 主题变量及使用边界

文字、背景、边框和交互状态使用 `--dsw-alias-*`，字体继承宿主。不要在组件中硬编码白底、黑字或品牌蓝，也不要给整个容器加透明度来制造“次要”视觉。

| 用途 | 首选变量 | 约束 |
|---|---|---|
| 窗口和浮层表面 | `--dsw-alias-bg-layer-1` | 根据宿主的对应表面选择；不要以为 layer-2 必然更灰 |
| 页面底色 | `--dsw-alias-bg-base` | 只作用于插件自己的区域，不覆盖宿主 body |
| 中性内容块、次操作填充 | `--dsw-alias-bg-module-platform` | 用于建议块、说明块等，避免卡片层层套卡片 |
| 正文、状态名称、操作名称 | `--dsw-alias-label-primary` | 状态名称不能依赖低对比的语义彩色文字 |
| 辅助标签和说明 | `--dsw-alias-label-secondary` | 辅助信息仍须可读 |
| 弱提示、非关键元信息 | `--dsw-alias-label-tertiary` | 不承载唯一的错误、进度或操作说明；使用前测对比度 |
| 主按钮填充、悬停 | `--dsw-alias-button-primary-fill`、`--dsw-alias-button-primary-hover` | 不手写浅色/深色两套按钮颜色 |
| 主按钮文字 | `--dsw-alias-label-primary-foreground` | 必须与主按钮填充配对 |
| 普通控件悬停、按下 | `--dsw-alias-interactive-bg-hover`、`--dsw-alias-interactive-bg-active` | 验证与实际底色合成后的结果 |
| 轻边框、分隔线 | `--dsw-alias-border-l3` | 区分结构即可，不给每一行都画框 |
| 成功、进行中、警告浅底 | `--dsw-alias-state-success-tertiary`、`--dsw-alias-state-business-tertiary`、`--dsw-alias-state-warn-tertiary` | 搭配主文字色，彩色图标只作辅助 |

变量名中的 `primary / secondary / tertiary` **不等于通用的文字／背景／边框配方**。例如当前主题的 `success-secondary` 是饱和绿色，把 `success-primary` 文字叠上去会看不清；`button-tool-bar-fill` 带透明度，也不能不经验证就当普通灰色按钮底色。

可选变量缺失时回退到语义相近的宿主变量，例如 `var(--dsw-alias-state-success-tertiary, var(--dsw-alias-bg-module-platform))`。若宿主核心主题尚未加载，应修复加载或注入关系，不能用一整套硬编码配色掩盖问题。

阴影优先使用对应原生表面的样式。没有可用变量时，可以保留一个轻量的中性阴影常量并在两种主题下验证；这不允许把正文或按钮的前景、背景颜色改成常量。插件不修改宿主主题属性，也不重新定义宿主变量。

### 字号 圆角与间距

以下尺寸是当前宿主基线和本插件默认值；存在可复用原生组件时以该组件为准。尺寸均为 CSS px，不按截图的物理像素反推。

| 元素 | 字号／行高 | 尺寸与间距 |
|---|---|---|
| 浮层标题 | 14／22，600 字重 | 与状态和关闭按钮对齐 |
| 主要正文、设置项名称 | 14／22 | 长文本自然换行 |
| 说明、标签、版本、时间 | 12／18 | 不把重要说明缩成 10 或 11px |
| 常规操作按钮 | 14／22 | 原生 md 高度 36，横向内边距 14 |
| 紧凑操作按钮 | 12／18 | 原生 sm 高度 28，横向内边距 10；换行时允许增高 |
| 图标按钮 | 图形 16 | 点击区域 28 × 28；图形不等于点击区域 |
| 浮层正文 | — | 默认内边距 16，分区间距 16，紧凑宽度可减为 12 |
| 控件之间 | — | 通常 8；标签与正文 6；紧密图标与文字 4 |

当前圆角变量为 `xs=4`、`sm=8`、`md=12`、`lg=16`、`xl=20`、`panel=28`。紧凑按钮用 `--dsw-radius-sm`，内容分组用 `--dsw-radius-md`，本插件浮层用 `--dsw-radius-lg`。先用变量，数值只作同尺寸回退。不要把所有按钮都改成 `999px` 胶囊；标签、开关或原生明确采用胶囊的控件可以使用。

## 3 控件和信息结构

### 操作按钮

同一操作区最多突出一个主操作，按用户下一步要做的事情选择。桌面底栏主操作放右侧，DOM 顺序与显示、键盘顺序一致；不要用 CSS `order` 只交换外观。

| 类型 | 外观和行为 | 本插件例子 |
|---|---|---|
| 主操作 | 宿主主按钮填充＋对应前景色 | 填入草稿 |
| 次操作 | 中性填充，普通 hover/active | 同步给 Agent、核对进度 |
| 图标操作 | 透明底、悬停底、清晰图标和可访问名称 | 右上角关闭 |
| 禁用或加载 | 原生 disabled/loading 行为，阻止重复提交 | 核对请求处理中；没有可写输入框 |

所有按钮显式写 `type="button"`，除非它确实提交表单。图标按钮提供本地化 `aria-label`；装饰图标用 `aria-hidden`。优先复用宿主图标，无法复用时使用统一尺寸的 SVG，不混用 Emoji、文字字符和多套线宽。焦点样式必须可见，且不被父容器裁切。

### 状态标签

标签表达状态，按钮执行操作。不可点击的状态标签不要做成按钮，也不能只用红绿圆点表达结果。

| 状态 | 建议显示 | 颜色语义 |
|---|---|---|
| 进行中 | 进行中，必要时附当前阶段 | business 浅底＋主文字 |
| 已完成 | 已完成；验收来源在邻近说明中明确 | success 浅底＋主文字 |
| 需要处理 | 需处理，给出下一步 | warn 浅底＋主文字 |
| 失败 | 失败原因摘要＋可用的重试操作 | error 图标／标记＋可读正文，不用整块红字 |
| 已停用或已归档 | 停用／归档，说明相关影响 | 中性底＋可读文字 |
| 数据过期或未知 | 待刷新／待核验 | 不继续展示看似最新的成功状态 |

“模型认为完成”“工具验收通过”“用户确认完成”是不同事实，视觉整理不能把它们合并成同一个已验证结论。后台服务“启动中”也不能显示为“运行中”。

### 浮层和长内容

浮层分成三个区域，不让整个窗口滚动：

```text
标题区  标题 · 版本 · 状态                         关闭
─────────────────────────────────────────────────
正文区  目标 → 当前步骤 → 完整计划 → 最近更新 → 下一步
        正文超高时滚动；关键说明靠近对应内容
─────────────────────────────────────────────────
操作区  更新时间                  次操作    主操作
```

- 标题和操作区不收缩；正文使用 `min-height:0; overflow:auto`。正文直接子元素不应被 flex 压扁。
- 在可用空间内给浮层限高，四周保留至少 12px；窗口不足时宽度随视口缩小，不设强制 300px 最小宽度。
- 锚点上方放不下时改用视口内位置；空内容自然收起，不固定一大块空白。
- 纯信息浮层提供一个清晰关闭入口和 Esc 关闭；关闭后焦点回到合理入口。可返回未保存表单的“取消”有独立语义，不按重复关闭删除。
- 状态、关闭和主要操作不能被长版本号、长标题或英文按钮挤出窗口。窄窗口允许按钮换行。
- 非模态浮层不随意声明 `aria-modal` 或锁住整页焦点；真正的模态确认应遵循宿主模态组件行为。

计划面板的特定规则：没有未完成步骤时，不显示空“步骤”标题；已完成步骤进入可展开的完整计划；“最近更新”解释变化，“下一步建议”给出可执行动作。兼容模式的验收来源说明保持可见，回执编号和运行日志等细节按需展开。

### 设置页和组件详情

设置页采用宿主的“左侧名称与说明，右侧控件”行结构；窄窗口转为上下排列。开关用于即时布尔设置，下拉用于互斥选项，危险操作使用明确的动词，不把所有控件都做成相同灰色按钮。

普通设置先显示能帮助用户决策的内容；安装路径、后端参数、日志和高级诊断放到高级区。下载、启动、运行、失败分别有状态文字；有可靠总量才显示百分比。失败后说明用户可以做什么，不能仅显示内部异常名称。

每个可独立启停的组件至少提供：本地化名称、一句话职责、关闭后的影响，以及与其他组件的关系。例如 embedding 管 Q8 进程，retrieval 管索引并借用向量；界面不能把“关闭检索”描述成一定立即关闭独立 Q8 服务。不要为一个底层组件额外制造一个同级设置入口，除非用户需要独立决策。

## 4 样式和组件的实现约束

1. 同一控件只有一套基础样式，通过 `data-*` 或明确变体扩展。修正已有规则，不在文件末尾叠加 v2、v3 皮肤覆盖。
2. 优先复用按钮、状态标签、设置行、说明文字等组件。当前单文件约束下，可先提取函数与 CSS 常量；不必为了样式统一引入新打包系统。
3. 选择器限定在插件前缀或根节点内，不写全局 `button`、`body`、`summary` 覆盖。不使用宿主构建后的散列类名定位组件。
4. 默认不用 `!important`。如宿主契约确有必要，在最小作用域注明来源和原因；不能用它对抗自己重复的样式。
5. 使用宿主插槽、主题和输入动作接口，不改宿主 DOM 来获得圆角或位置。变更样式不能改变自动发送、输入草稿、会话隔离等行为边界。
6. 本地化的可见文案和可访问名称走现有 locale 流程；长英文、路径、错误文本要换行或在有完整查看入口时截断。
7. 读取宿主主题自动适配明暗。不要在插件内复制一套跟宿主独立的主题状态。

现有代码并不自动成为规范范例。历史设置页仍有局部 `!important` 和硬编码值；触及这些控件时应按本规范收拢，并记录保留项。文档新增不表示全仓控件已经完成整改。

以下为使用宿主变量的最小样式示例；它不提供事件处理、焦点管理或浮层定位：

```css
.dshp-panel {
  display: flex;
  flex-direction: column;
  overflow: hidden;
  color: var(--dsw-alias-label-primary);
  background: var(--dsw-alias-bg-layer-1);
  border: .5px solid var(--dsw-alias-border-l3);
  border-radius: var(--dsw-radius-lg, 16px);
  font-family: inherit;
  font-size: 14px;
  line-height: 22px;
}
.dshp-panel__head, .dshp-panel__foot { flex: none; padding: 12px 16px; }
.dshp-panel__body { flex: 1 1 auto; min-height: 0; overflow: auto; padding: 16px; }
.dshp-panel__actions { display: flex; flex-wrap: wrap; justify-content: flex-end; gap: 8px; }
.dshp-button {
  min-height: 28px;
  border: 0;
  border-radius: var(--dsw-radius-sm, 8px);

.dshp-button:hover:not(:disabled) { background: var(--dsw-alias-interactive-bg-hover); }
.dshp-button:active:not(:disabled) { background: var(--dsw-alias-interactive-bg-active); }
```

## 5 可读性和验证标准

本插件的正文、辅助说明、状态名称和按钮文案通常是 12–14px，应按普通文字测量，前景与最终背景对比度至少 **4.5:1**。不要把 14px 当作大号文字而放宽标准。[W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

识别控件或状态所必需的图形、焦点提示与邻接颜色至少 **3:1**。装饰分隔线和带有清楚文字的按钮不必因此加粗边框；禁用控件有标准例外，但不能把关键提示伪装成禁用状态来降低可读性要求。[W3C 非文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

在真实宿主主题下读取计算后的颜色。含透明度时先与实际底色逐层合成再计算；不能只比较两个变量名，或把透明背景当成黑色。视觉检查还要看实际字号、字重和屏幕缩放。

| 验证组 | 最少场景 | 通过标准 |
|---|---|---|
| 主题 | 浅色、深色、打开界面后切换主题 | 无遗留硬编码底色，文字和关键图标达到对比度要求 |
| 视口与缩放 | 常规桌面、320px；紧凑浮层补 280px；125% 和 200% 缩放 | 无横向溢出，标题、关闭、按钮可用，必要时正文滚动 |
| 内容 | 空状态、全部完成、长标题、长计划、长错误、英文文案 | 无空标题和无意义留白，长内容不压扁或遮住操作 |
| 异步状态 | 首次加载、刷新、失败、重试、禁用、数据过期 | 状态准确，按钮不会重复触发，旧响应不覆盖新会话 |
| 交互 | 鼠标、Tab／Shift+Tab、Enter／Space、Esc | 焦点可见且顺序合理；关闭、展开和主要操作均可完成 |
| 行为回归 | 本次移动或重构过的操作 | 原回调、禁用逻辑和语义不变；如填入草稿仍不自动发送 |

矩阵是按改动选择的验收要求，不是每次修改都重跑全仓所有场景。纯文档修改校验事实、示例和链接即可。首次建立或重做某类界面时覆盖整组；之后至少重测改动涉及的主题、状态与交互。

能在浏览器渲染的改动，应检查实际渲染结果。DOM 快照和 CSS 字符串断言不能证明可读性或未溢出；针对事件回调、状态分组、视口边界等行为使用有效的回归测试。加载新客户端后确认 build 标记或资源内容，避免把旧缓存截图当成新代码验收。

PR 的验证记录可直接使用以下模板，保留真实结果，不预填“通过”：

```text
原生参考：DSH 版本 / 对应页面 / 读取的主题与控件来源
改动范围：界面与共享控件；是否改变交互或状态语义
视觉检查：主题、视口、缩放、语言、状态；截图或可复现步骤
对比度：元素 / 前景 / 合成后背景 / 比值
行为检查：关键回调、键盘、禁用/加载、会话切换
自动化结果：实际运行命令与结果
真实 DSH 验收：已完成的场景；未完成项与具体原因
保留差异：与原生样式或本规范的差异及理由
```

## 6 常见问题与修正方式

| 不应接受的做法 | 修正方式 |
|---|---|
| “都用了绿色变量，所以已完成标签没问题” | 实测组合；浅语义底配主文字，图标作辅助 |
| “用了主题变量，所以天然符合 DSH” | 同时核对控件类型、尺寸、圆角、密度和交互；变量不能替代布局设计 |
| 每个新窗口重新写一套按钮 | 复用同一基础控件和变体，手工确认按钮也纳入 |
| 在文件末尾追加第三套覆盖，继续堆 `!important` | 合并为一套规则，删除冲突来源 |
| 为了紧凑把说明变成 10px、整体降低 opacity | 降低信息密度、折叠次要内容，保留可读字号和文字颜色 |
| 把“Q8 启动失败”等关键信息藏进日志 | 常规界面显示摘要和下一步，日志作为补充 |
| 同时堆放重复关闭按钮、空步骤标题、大块空白 | 按实际信息和操作语义整理分区 |
| 只截浅色、短内容的一张图就交付 | 按验证矩阵补足相关场景，区分隔离渲染与宿主验收 |
| 为了外观修改宿主 DOM 或自动发送行为 | 使用插件插槽和公开动作接口，在插件范围内完成样式调整 |

## 7 给下一个插件复用的任务指令

复制本文件到新插件的 `docs/`，并在该仓库的 `AGENTS.md` 与开发说明中建立入口；不要只把链接留在一次聊天里。保留通用规则，将计划面板、Tab 和 Q8 的特例替换成新插件自己的行为边界。

可以直接向开发 Agent 发送：

> 实现界面前先阅读 docs/ui-design-contract.md。以当前安装的 DSH 原生页面和主题变量为依据，确认基础控件可加载后再复用；不能加载则在插件作用域内实现同等样式和行为。先说明界面类型、主要操作、信息顺序和状态覆盖，再完成实现。禁止叠加新的皮肤覆盖、用变量名称猜对比度或只检查浅色短内容。提交时附相关主题、视口、状态和行为的验证结果，真实 DSH 未覆盖的部分明确列出。用户当前要求优先，普通设计取舍不增加审批步骤。
