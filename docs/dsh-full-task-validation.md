## 本轮发现和修复

- **正文误作状态**：源码里的 `Task is not in progress` 或错误示例会让成功的结构化 read_file 回执变成 pending/failure。现在仅在识别状态时排除 JSON content 正文，仍核对外层 error/isError/exitCode/status/pending 与输出诊断。正文中的 exit code 0 也不能伪造成功。
- **大文件写入丢失路径**：旧逻辑遇到超过 4000 字符的参数会全部清空。现在保留有界、脱敏后的短标量身份参数，丢弃大正文；路径匹配恢复，仍需后续回读与测试。

新增 4 项回归；插件 **198/198，0 skip/todo**。首轮账本 9 阶段有 7 阶段漏标完成，没有提前完成。用同一原始日志和完整回执提案做确定性重放，新校验 **9/9** 正确；这项重放没有冒充新模型实测。随后重启原生 DSH，实际回读、重测、核对报告和标记，约 **29.19 秒**得到 done/done/done。
