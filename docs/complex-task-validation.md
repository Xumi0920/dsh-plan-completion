# QQAgent 与文章/工作流复杂任务隔离验证

日期：2026-11-04。结论：存在可复现的策略缺口，不能宣称业务全 PASS。官方 Q8 无需因为这些结果改权重；主要问题是回执覆盖、验收条件的含义和生成模型使用证据的方式。

## 范围与隔离

从用户指定的 QQAgent 图像故障任务，以及由文章阅读扩展出的多阶段工作流，提炼合成需求。真实聊天只在本地用于理解任务结构；测试输入重新编写，不包含私有源码、真实群号、账号、文章原文或历史聊天摘录。公共材料只记录合成任务。

执行模型只有 DSH 当前的 **DeepSeek-V4.1-Flash**。计划助手 reasoning=off；原生 Agent 保持当前 max 思考与原生上下文配置。官方 `dsh-qwen3-embedding:q8_0` 权重不变。没有 Codex CLI/模型参与测试执行；没有发 QQ/飞书消息、重画图像、登录文章服务或部署生产配置。

本轮分为两类证据，不能混称：

1. **检索策略消融**：18 个六步场景 × 2 次 × 3 组 = 108 次真实 DeepSeek 计划更新。DSH 已提交事件格式由合成夹具提供，调用生产的 collect/buildPrompt/parse/validate/patch 函数；不是 108 次主 Agent 自主完成真实项目。
2. **原生 DSH 连续执行**：真正启动隔离 DSH，让主 Agent 通过唯一的 `exec` 工具调用本地工作流模拟器。工具名称不代表系统 shell；命令只能匹配合成操作标识，业务副作用全为模拟。计划插件从实际产生的原生事件更新状态。计划验收条件预先固定，不包含“模型自行设计验收条件也正确”的证明。

本轮没有重跑近 1M 压力或真实 QQ/飞书端到端业务验收。此前长上下文结果见其他验证文档。

## 对照设计

每个任务包含六步，最多 14 条必须引用的回执。覆盖全部完成、部分完成、最新失败、未知/缺回执、错误对象、重写后旧验证、仅有英文意图、失败后恢复、受理型弱验收等九种情况。关键证据埋在最近 24 条工具记录之外，混入 40 组无关诊断、乐观助手声明和错误压缩摘要。

三组使用同一模型、同一提示词、同一修复后的状态校验、同一 temperature=0、maxTokens=2500、20 秒调用上限，轮换调用顺序。只改变检索输入：关闭 RAG；PR `ee082c62` 的原 typed 检索；新增逐验收项覆盖的 typed 候选。因而这是检索消融，不是旧版与新版整套插件的直接胜率比较。

“整计划准确”要求六个状态全部匹配事先写好的独立验收项预期；“误完成”指预期未完成却落成 done；漏完成反之。召回率按最新目标回执计算，包含确定性精确目标查找，不是纯向量余弦召回。样本故意放大多目标 top-K 瓶颈，结果不能外推为所有日常任务的准确率。

| 组别 | 整计划准确 | 目标回执平均召回 | 误完成/未完成机会 | 漏完成/完成机会 | 更新中位数 / P95，ms |
|---|---:|---:|---:|---:|---:|
| 关闭 RAG | 4/36 | 0.0% | 0/64 | 152/152 | 1159 / 1559 |
| 原 typed Q8 | 4/36 | 23.2% | 0/64 | 152/152 | 1319 / 1831 |
| 候选 Q8 + 回执覆盖 | 33/36 | 100.0% | 0/64 | 12/152 | 2103 / 2400 |

更新时间包含查询检索、模型响应、解析与状态校验，不含后台初次索引。原 typed 与候选初次索引中位数分别为 1827.9 / 1820.8 ms；它们对全部 18 个场景均使用真实 Q8。数据详见 [JSON](data/complex-task-20261104.json)，包括逐案失败状态、检索时间和索引时间。

中文查询的英文意图与人类约束另外用明确 purpose 测试，避免在计时前预热其中一组；来源混淆和命中计数见 JSON。这不代表计划更新的 mixed 查询每次必然包含所有英文思考。

## 发现与修复

### 1. 多步骤回执被 top-K 挤掉

原策略按“回执、调用”交替加入候选，topK=5 时，14 条必要回执只带回前三条；六项验收的第一步都凑不齐，更后面的步骤也被饿住。提高向量维度或微调 Q8 不能消除这个容量问题。

候选增加不占语义 top-K 的 `targets`：最多 7×6 项、额外 12000 字符，只传回执 ID、调用/结果序号、状态和字段核对布尔值。预算不足整组省略并明确提示，不截断 ID；不复制正文、参数或原始字段值。仍受当前会话索引的 FIFO/TTL 约束，不是无限历史账本。模型提出 done 后，仍由原始事件校验器复查。

### 2. 召回完整反而暴露弱验收误判

中间版本已经召回全部回执，却将 `accepted=true, delivery=unknown` 当作送达：两类任务各两次，共 **4/4 误完成**。中间失败记录保留，未用后续结果覆盖它。

已补校验：若结构化回执只给出受理标志（`accepted=true` 或 `status/state=accepted/submitted`），既有条件必须有明确 `expect`，否则保持待核验。真正以“提交请求”为目标的步骤可明确核对 accepted；“确认送达”需要 delivered 等相应事实。新增回归覆盖这一区分，不能只靠提示词。

### 3. 仍然存在语义范围缺口

确定性反例仍可复现：若一个既有步骤标题是“确认图像送达”，但它的条件已经错误地设为 `expect accepted=true`，受理回执仍能通过校验。通用匹配器只证明条件成立，不能证明这个条件足够代表人类目标。此项 **FAIL / 待设计改进**，不是回归套件已修好的能力。

跨步骤也还没有完整依赖图。重新写入会使同一复合步骤内的旧验证失效，但不会自动使另一个独立步骤的测试、部署和业务验收全部失效。复杂任务应把对象 ID、不可变版本/内容哈希以及必要前置验收绑定到条件，不能仅凭模糊标题或可重复使用的 r2 标签推断依赖有效。

另有生成模型取得正确证据后仍保守不更新的情况，逐案列于 JSON。这里“整计划未全对”与“错误标记完成”分别统计；没有通过放宽预期或删除难例宣称全 PASS。

## 原生 DSH 连续执行

两任务各经历“先完成前三步 → 后续仅受理/结果未知 → 注入最新故障 → 恢复并只读核验”。模拟器收到 **39** 次实际工具调用，原生模型/计划助手共 **80** 次调用；原生阶段状态准确 **8/8**。已检查原生 v4 事件关系。主 Agent 输出上限使用原生模型配置，计划助手实验上限为 2500。

| 阶段 | 六步实际状态 | 与预期一致 | 阶段耗时，秒 |
|---|---|---|---:|
| qq-partial | done / done / done / todo / todo / todo | True | 18.1 |
| qq-unconfirmed | done / done / done / done / doing / doing | True | 12.1 |
| qq-failed | done / done / blocked / done / doing / doing | True | 8.0 |
| qq-recovered | done / done / done / done / done / done | True | 10.1 |
| workflow-partial | done / done / done / todo / todo / todo | True | 18.1 |
| workflow-unconfirmed | done / done / done / done / doing / doing | True | 10.0 |
| workflow-failed | done / done / blocked / done / doing / doing | True | 8.0 |
| workflow-recovered | done / done / done / done / done / done | True | 11.1 |

主模型阶段耗时包含思考、工具往返、插件更新及等待稳定；不能与上表单次计划更新毫秒数混比。模型调用中因新工具边界撤销旧计划请求的 ABORTED 单独记录，不直接视为云服务故障。

## 输出预算、资源与隐私

额外用当前默认 800 输出 token 做四个复杂整表更新探针：准确 3/4，解析/调用错误 0。四次均正常 stop，未观察到 max-tokens 截断；其中一次保守漏标，样本不足以归因于输出上限。这是单次请求探针，没有把生产 JSON 修复重试算入其中。三组主对照均用 2500，不能把该延迟直接当成用户现有低预算配置的结果；生产配置没有被改动。

计划消融进程峰值 RSS **150.4 MiB**；原生模拟进程峰值 **237.5 MiB**。Ollama 报告 Q8 驻留显存约 **2.66 GiB**，不是新增独占显存测量，也不是整机峰值。

当前账号凭据与生产配置仅在本机只读读取用于既有授权路由；前后哈希保持不变。生成请求只允许既有 `api.deepseek.com` 端点，嵌入只允许 loopback；公共发布集另做本地凭据精确值、私钥标志和已知来源账号/聊天标识扫描。此扫描不是通用个人信息识别。模型见到的是合成数据，原始聊天和凭据没有作为测试材料发送。

新增 8 项回归，全套 **206/206、0 skip**。覆盖多目标挤占、未知/失败/恢复、旧验证、完整组预算、无正文/参数泄漏、离线、会话隔离与明确受理验收。回归通过不等于上面的业务语义缺口已通过。

## 复现与决策

`node scripts/benchmark-complex-tasks.mjs` 需要显式提供四个本机路径变量：`DSH_COMPLEX_BRIDGE`（经审查的当前 DSH 适配器）、`DSH_COMPLEX_LLM_MODULE`、`DSH_COMPLEX_BASELINE`（ee082c62 的 host 目录所在仓库根）、`DSH_COMPLEX_OUTPUT`（已创建的输出目录）。脚本会产生真实模型调用；公共脚本不发现或复制凭据。确定性回归直接运行 `node --test`。

建议维持官方 Q8：RAG 提供背景与证据位置，独立回执校验维护执行事实，DSH 原生模型负责拆解和解释。下一优先级是验收范围与跨步骤版本依赖，并在真实计划规模下继续评估输出预算；本轮没有证明必须提高生产预算，也不支持先微调权重。保持 PR 为 Draft，暂不作为真实交付自动完成的全量放行依据。
