# 接近 1M 与连续原生自动压缩：隔离验证

> 后续更新：本报告保留当时的测量与失败记录。复合步骤误判已另行修复；新增 96 次真实 DeepSeek RAG 开关/策略对照与故障恢复结果见 [对照验证](q8-rag-ab-validation.md)。本轮没有重复近 1M 主 Agent 压测。

日期：2026-11-04。候选 PR #1，保持 Draft，未合并、未安装到正式 DSH。

## 结论与配置

当前账号实时模型为 DeepSeek-V4.1-Flash（`deepseek-account/deepseek-flash`），目录窗口 1,048,576 token；主模型 Max、计划助手 Off，原生压缩摘要 High。实际 DSH 0.2.1-rc.5 独立 home、端口 18094/18095、合成数据，无真实工作区工具。

官方 Qwen3-Embedding-0.6B Q8_0 在 Ollama 本机运行；1024 维、嵌入窗口 8192。RAG 只辅助计划/补全，未裁剪主 Agent 的请求历史。主上下文压缩由原生 `dsh-compaction-basic` 的压力逻辑自动触发；没有用 `/compact` 冒充自动压缩。

近上限测试显式把主模型单次输出上限设为 **4096**，以留出实际百万 token 输入空间；原生阈值比例 0.8、headroom 65536、retainRatio 0.16、摘要上限 65536 均未降低。计划补丁/重写上限为 1000/1800。这个实验配置不修改用户正式配置，也不代表默认 256000 输出预留可以和 1M 输入同时装进 1M 窗口。

## 实际模型调用

输入以服务端 usage 的 inputTokens + cacheReadTokens + cacheWriteTokens 计数，排除输出、避免重复计算 totalTokens。字节、字符、累计 token 和 UI 四舍五入显示不作为实际输入计数。

| 连续轮次 | 压缩前主请求实际输入 token | 首个可见文本 | 主请求总时间 | 自动压缩摘要调用 | 自动压缩轮端到端观察 |
|---|---:|---:|---:|---:|---:|
| 1 | 1,036,143 | 19.43 s | 20.22 s | 20.47 s | 30.25 s |
| 2 | 1,000,188 | 16.96 s | 17.62 s | 18.80 s | 28.33 s |
| 3 | 1,000,381 | 16.36 s | 16.94 s | 19.71 s | 30.31 s |

端到端观察包含压缩、压缩后的主模型回复、计划助手、2 秒轮询及额外 2 秒稳定等待，不能视为精确 UI p95。主请求耗时为真实 API 流结束时间。主请求首个可见文本包含 Max 思考等待，不是首个 reasoning token。

另有独立直连校准：2,000 行合成档案得到 69,136 输入 token，随后实际 **1,001,526 输入 token** 请求成功（23.08 秒）。输出保留四条约束，写入/失败测试/未执行报告的简短判断符合合成题设；这个直连案例没有插件硬校验，不把它混作端到端插件验收。

恢复原生 **256000 输出预留**后另测：主请求 **742,700 输入 token / 11.41 秒**；随后原生自动压缩第 4 次成功，摘要输入 **595,044 token / 14.08 秒**，后续主请求 **150,302 token / 4.38 秒**。该压缩轮端到端观察 24.25 秒。默认预留对应压力上限约 727,040 token，早于 1M 是正常行为。

## 计划与约束

- 前三次近上限填充和自动压缩，3 个未调用工具的步骤始终为 `todo/todo/todo`。中文任务、英文准备执行描述、摘要均未变成完成回执。
- 隔离进程重启，从原生日志及计划文件恢复。随后原生 Agent 实际调用两个**纯内存实验工具**：write_file 返回成功，exec 的固定 npm test 场景返回 exitCode=1，报告工具未调用；插件得到 `done/blocked/todo`。没有执行真实 shell 命令或写入真实工作文件。
- 第 4 次自动压缩后 `done/blocked/todo` 仍保持，成功/失败核对引用原始工具回执；所有完成阶段均通过官方 v4 日志关系校验。
- 新旧用户约束按来源 seq 保留；后来的“允许内存实验工具”更新没有被旧的“不执行工具”覆盖。计划摘要最多 6 条，源约束账本独立于这 6 条展示。
- 新增 `user_constraint` 来源账本与 FIFO 向量索引分离，按需重建，自带来源 ID、seq 与会话归属。无需命中 top-K，即使向量离线或查询无命中也进入计划提示；生成的 checkpoint/runtime-context/助手思考不能成为约束来源。
- 账本最多 24 条、总计 6000 字符、每段 400 字符；溢出保留最早 8 条及最新修改，并显式标记不完整、在界面提示复核。它是保守关键词提取，不能保证理解所有隐含约束；不是无限记忆或权限求解器。
- 75 轮／2058 步／8192 片段回归：普通早期片段仍会淘汰，最早隔离约束由独立账本保留，`firstConstraintRetained=true`。

## 延迟与资源

- 前三次大输入场景的计划助手 API：**1.06–2.04 秒**，所有 17 次主模型/摘要/助手调用成功。并发新边界取消旧助手请求的场景另在工具回执测试中真实发生，过时结果未覆盖新状态。
- 大索引下记录到的总检索耗时约 **201–368 ms**，包括本地评分；250 ms 是向量请求等待预算，**不是全检索硬上限**。索引积压时有词法降级，尚未索引的英文记录可能无法获得语义召回。
- 三轮 native Node 进程采样 RSS **136.3–354.9 MiB**；活跃测试段 CPU 累计约 **7.72 秒**，只含该 Node 进程，不含 Ollama/GPU、浏览器或其他程序。
- Ollama `api/ps` 的 Q8 模型显存分配约 **2.66 GiB**，不是 GGUF 文件大小或整机显存总量。主机物理内存 API 约 63.66 GiB。未取得完整推理后端进程树 CPU/RAM，不能将 Node RSS 当作全系统总占用。
- 2061 个本地观察边界：扫描中位 **44.46 ms**，p95 **85.99 ms**，最大 **115.33 ms**，累计 **92.19 s**，基准进程 RSS 增量 **320.7 MiB**。该本地基准用确定性假向量隔离扫描成本，仍是全量扫描；不冒充 Q8 建索引速度。

## 失败、边界与隐私

补充工具夹具首次接入收到两次 HTTP 400：服务端要求至少一个非延迟加载工具。仅在实验桥接器对这两个合成工具显式设置 `defer_loading=false` 后通过；这一桥接适配没有进入插件源码。此前三次无工具的百万 token/自动压缩测试不依赖此适配。失败阶段均未产生伪造完成状态。

主模型有一次把“保留原生长上下文”解释成“不压缩”，这是回答措辞不准确；实际原生日志已记录成功压缩。应将要求表达为保留 DSH 原生上下文管理与自动压缩机制。工具回执门槛只核验精确工具目标，不能验证模型自行附加的复合条件（例如标题里的“回读校验”）；对应完成结果仅证明工具声明的操作。

正式 DSH 根配置、desktop 配置、凭据文件前后 SHA-256 一致。仅只读使用当前账号凭据；没有复制凭据到插件或公开材料。合成内容发送到当前 DeepSeek，嵌入仅发本机 Ollama；未导入真实聊天和工作区文件。RAG 与向云端发送检索片段的开关仍默认关闭。账本同样在脱敏后建立、只存 RAM，随会话 TTL/重置/卸载清理；原生合成会话与计划文件仅留在隔离 home。脱敏是尽力最小化，不等于完整匿名化。

仍未覆盖：长会话语料的统计准确率、随机丢包/限流与费用核账、同样大输入下严格关闭 RAG 对照、全索引冷启动耗时、工作区级权限与增量索引。有限合成样本通过，不等于所有生产长任务已验收。
