# 统一进度协议：隔离验证

日期：2026-11-04。版本基线 `b9e37da`。当前候选的定向计划对照、原生 DSH 阶段和本地回归通过；这不是所有业务场景或真实交付的全 PASS。保持 Draft PR，先不合并。

## 实现与范围

[协议说明](progress-protocol.md)定义了计划助手的 `progress.version=1` 信封、宿主验收版本与事件序号边界，以及精确绑定前置验收版本的依赖图。新执行或上游改版会撤销下游旧证明。模型不能通过改 status、删步骤或弱化范围绕过校验。delivery 要求 delivered=true，不能用 accepted=true 代替。

主 Agent 保留原生回复和长上下文，协议只用于旁路计划助手。当前模型路由实测为 **deepseek-account / deepseek-flash / DeepSeek-V4.1-Flash**，原生上下文配置 1,048,576，主 Agent reasoning=max、输出上限 256000；计划助手 reasoning=off。向量模型为官方 Ollama `dsh-qwen3-embedding:q8_0`，权重没有微调。

测试仍仅由 DSH / 当前 DeepSeek 执行。QQAgent 图像故障与小黑盒文章扩展工作流仅提供任务结构，全部模型输入重新编写为合成数据。没有 Codex 模型执行测试，没有真实 QQ/飞书消息、登录文章服务、私有代码外发或生产部署。

## 计划更新对照

22 个六步场景 × 3 组 × 1 次，共 **66 次真实 DeepSeek 计划更新**。覆盖完整/部分完成、故障、未知结果、错误对象、旧验证、英文思考、恢复、弱验收、明确错误的 accepted 条件及验收改版。状态预期在执行前固定；不是按模型输出修改答案。

旧 Q8 组冻结 `b9e37da` 的 host 代码，16 个基线文件与 GitHub blob 一致。新协议两组使用相同提示、宿主协议和模型配置，仅切换 RAG。三组轮换顺序，temperature=0、2500 输出 token、20 秒上限。本比较包含**架构改变**，不能把新旧差异单独归因于检索效果；既有验收条件由夹具给定，新协议在调用模型前已经按原始回执重建状态。

## 原生 DSH 连续执行

实际启动两套全新隔离 DSH_HOME，按关闭 RAG、Q8 的顺序串行执行，避免同时竞争模型/嵌入资源。每组两类任务各九阶段：部分完成 → 仅受理/未知 → 最新失败 → 恢复 → 上游重写 → 下游复核 → s2 验收升版 → s3–s6 依赖批量升版 → 新版重新执行。

唯一可用工具名为 exec，但实现是**内存模拟器**，只接受预先注册的操作标识，不是系统 shell。模型实际调用它并产生原生 v4 事件，插件据此更新计划；计划定义预先播种，未验证模型从零设计所有验收条件的能力。

| 组别 | 状态与验收版本均匹配 | 误完成 | 实际工具调用 | 阶段中位数 / P95 | 进程峰值 RSS |
|---|---:|---:|---:|---:|---:|
| 关闭 RAG | 18/18 | 0 | 74 | 11.57 / 20.08 s | 228.08 MiB |
| 官方 Q8 | 18/18 | 0 | 74 | 13.06 / 19.08 s | 236.31 MiB |

共 **36/36 阶段、148 次工具调用**。验收版本不是只看状态推断：修订 s2 后为 [1,2,1,1,1,1]，四个下游提交后为 [1,2,2,2,2,2]，旧回执全部不能追认新版完成。全部原生 v4 事件关系校验通过。两组主模型与计划助手合计 345 次调用，其中 116 次为观察到新工具边界后撤销旧计划请求的 ABORTED；其他模型错误为 0。

阶段耗时包含原生思考、多次工具/模型往返、插件更新和每阶段 3 秒稳定等待，主/助手请求可能重叠。它不是单次检索延迟，也不等同真实 QQAgent 或文章工作流的业务耗时。

## 中间失败与对应修复

失败日志保留在本地，公开 JSON 记录各次失败阶段及原始文件 SHA-256：

1. 初始原生关闭 RAG：严格状态+版本仅 13/18。模型把验收定义放到旧 changes，事件本身没有 acceptance/completion。宿主拒绝，但旧版仍存在。补完整事件示例、明确修复错误和提示。
2. 格式修复后的 Q8 与关闭 RAG：各 16/18。模型有时只提交四步依赖中的第一步。宿主正确阻止其他步骤完成，但建议文本仍可能声称可以收尾。补同批按拓扑顺序提交全部修订的规则；宿主对被拒绝提案或失效依赖显示核验提示。
3. 最终两组全新实例各 18/18。前述失败没有从测试集删除，最终预期同时校验状态和验收版本；不把“状态看似正确、版本没更新”算通过。

首次 132 次计划助手探索也保留在 JSON 的 pilots 中，不混入最终 66 次性能统计。

## 资源、隐私与剩余边界

计划助手对照进程峰值 RSS **150.92 MiB**。Ollama 当前报告 Q8 驻留显存 **2.66 GiB**，是驻留量，不是本轮额外独占显存或整机峰值。未对 CPU/GPU 总占用或不同硬件作外推。

生产配置、当前模型凭据和隔离生产哨兵前后哈希一致。生成请求仅到授权的 api.deepseek.com 路由；嵌入仅 loopback。公共 PR 文件执行真实本机凭据精确值、已知来源聊天/账号标识及私钥标志扫描，未命中真实凭据/来源标识。已有脱敏回归中一个仅含 secret 文本的 PEM 标记夹具单独人工复核，不作为真实私钥泄露。

这不是“零隐私风险”：开启外部计划模型后，选中的脱敏证据仍会发送给该模型；本地持久化计划可能保留任务名称/目标路径。脱敏不是通用 PII 检测，scope、验收语义和依赖设计仍需复核。旧计划没有 acceptance 时仍兼容旧逻辑，必须显式建立版本化验收才获得此保证。

本轮没有再跑接近 1M token、连续原生自动压缩或真实 QQ/飞书端到端业务；保留原生上下文配置和既有长会话回归不等于本轮重测它们。历史压力数据继续保留。重复上游执行保守地使下游失效，即使数据实际未变；原始日志与向量索引都有容量上限，不是无限工作区记忆。

## 复现

- 回归：`node --test`，不需要模型账号。
- 真实计划对照：`scripts/benchmark-progress-protocol.mjs`。显式提供 `DSH_PROTOCOL_BRIDGE`（经本机审查的当前 DSH 模型适配器）、`DSH_PROTOCOL_LLM_MODULE`、`DSH_PROTOCOL_BASELINE`（b9e37da 的仓库根）、`DSH_PROTOCOL_OUTPUT`（已创建输出目录）。三组共 66 次真实模型调用。
- 原生模拟：`scripts/benchmark-progress-native.mjs`。显式提供 `DSH_PROTOCOL_RUNTIME`（已安装 DSH 的隔离运行时目录）、`DSH_PROTOCOL_BRIDGE`、`DSH_PROTOCOL_OUTPUT`，分别设置 `DSH_PROTOCOL_RAG=off/q8` 串行运行。运行时 node_modules 中插件需指向本次候选。脚本拒绝复用同名测试 home/project，只提供模拟器工具，本地监听 18109/18110。
- 两个公共脚本都不发现或复制凭据；适配器由操作者显式提供。测试会产生真实模型请求，原始输出留在指定本机目录。公共 JSON 不包含原始聊天、凭据或模型思考全文。
