# 统一进度协议：接近 1M 与连续自动压缩验证

日期：2026-11-04。基线：PR #1 的 f5cdf6c。本轮最终代码的 10 个关键源码 SHA-256 随结果保存，两组相同并与本地待提交源码一致。仅使用隔离 DSH 的当前 DeepSeek，Codex 不作为被测执行模型。

**最终两组均 26/26 阶段符合预期，合计 52/52；每阶段同时比较六个步骤的状态和验收版本。样本中完成误判、漏判均为 0。** 12 个主模型请求实际输入为 1,000,902–1,007,155 tokens；四个独立会话各连续自动压缩四次，共 16 次。全部 231 个回归通过，无跳过。该结果支持本轮协议修复，不能推导所有真实长任务都已通过。

## 隔离方式和测试口径

- DSH 0.2.1-rc.5；模型目录实时读取为 DeepSeek-V4.1-Flash，contextWindow=1,048,576。主 Agent reasoning=max，计划助手 off，原生压缩 high；通过既有只读适配器使用当前模型，不复制账户凭证。
- 两个场景为 QQAgent 与文章/工作流的合成模拟器。每个场景六个步骤，包含复合测试、部署就绪、送达与去重验收。预置验收定义，后续修订由真实模型通过插件协议提交；这不是模型自主发现验收条件的测试。
- 原生 Agent 实际调用 allowlist exec 模拟工具，生成真实 DSH v4 日志。模拟器不执行 shell，不读取私人任务内容，不调用 QQ、飞书或文章站点。
- 每组独立 home、会话、工程、存储目录；关闭遥测和实际业务工具，仅监听 loopback。生产配置/凭证和隔离哨兵的前后 hash 全部一致。
- 原生自动压缩参数保持 thresholdRatio=0.8、headroom=65536、retainRatio=0.16、摘要输出上限65536；没有调用 /compact 或手动触发压缩。
- 接近1M阶段只在隔离主模型适配层把输出保留量设为4096，让实际输入接近窗口上限。随后每个场景恢复原生256000输出保留量，再验证一次原生阈值自动压缩。未修改生产配置。
- 长测计划助手输出预算为2500；仓库默认patch/rewrite仍为800/1200。800预算的重放探针已通过，但不代替默认预算下的整套原生长测，不能把本轮结果称作默认配置的全面验收。
- tokens 来自服务 usage：inputTokens + cacheReadTokens + cacheWriteTokens；不是字符数或累计多轮 totalTokens。所有有 usage 的请求均校验输入加输出等于 totalTokens。
- 旧代码 r1 按 off→Q8，中间修订 r2 按 Q8→off；r3 因用户暂停，在关闭组完成4阶段后停止，不计入对照。恢复后全新目录 r4 按 off→Q8 完整重跑，两组使用相同最终代码。组间不并发，但共享机器和云端缓存/网络环境；每组一轮，不宣称因果上的性能优胜。

## 发现的问题与修复

初轮旧代码关闭 RAG 为19/26；Q8为26/26，完成误判均为0。关闭 RAG 的 QQAgent 场景在依赖修订阶段遗漏下游版本，后续长期保守地 blocked；其中 17 个步骤×阶段漏报完成。保留初轮失败数据，没有把失败轮删除后称原实现全通过。

第二轮 r2 关闭组仍只有 20/26，完成误判0、漏判16（步骤×阶段）。两个场景都曾将定义修订误解为需要先有执行回执，晚一轮升版使刚执行的回执落在新边界之前。最终修复明确：提交验收定义是元数据操作，不需要执行证明；done 则必须有新版原始回执。同时在邻近输出 schema 中提供带事件的 op=none 示例，避免被空事件示例诱导延后修订。r1/r2失败数据均保留。

修复包含以下内容：

1. 提示明确 plan.steps 是宿主当前定义；原生助手声称“缺少定义/接口”不能覆盖宿主已提供的条件。新增 dependencies_proposed，只提交依赖引用，宿主复用完整 scope/completion。仍校验当前版本、禁止删除依赖和循环，宿主递增版本并建立新的执行边界。已有完整 acceptance_proposed 继续兼容。
2. RAG worker 按会话轮流处理一批，避免旧会话的巨大积压长期占据嵌入队列。旧 Q8 的第二场景在 initial 到 auto-2-revise 均 indexed=0；调度修复后的 r2 首轮从一次 lexical 过渡到 hybrid（indexed=7），首个百万阶段查询时 indexed=40。最终 r4 的实际查询模式另见下表和逐阶段数据。新历史大批进入、FIFO淘汰后仍有 indexed=0 的词法回退；本轮没有宣称索引始终完整。
3. 仓库审查发现历史 host/job.js 不是实际入口，却被旧文档写成可直接替换生产编排。回归复现其不能校验版本化计划；本轮提前拒绝这类计划，模型/提交/发布不发生。生产原本使用 index.js，不能把此发现说成当前生产绕过。另拆出 progress-schema.js，保持单插件和兼容导出。

第一次诊断用同一 DSH 模型重放失败现场，两个场景×800/2500输出预算共4/4通过，但完整 r2 仍暴露缺陷，说明短探针不足以替代长测。明确“定义修订无需执行回执”后，再用 r2 的实际误导回复做两场景×两预算×两次重放，8/8通过且全部返回四个 dependencies_proposed。最终完整长测才是主要验证结果。
