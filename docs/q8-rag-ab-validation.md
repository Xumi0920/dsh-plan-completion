# 复合验收与 Q8 检索对照（2026-11-04）

本轮继续使用官方 Qwen3-Embedding-0.6B Q8_0，没有微调。所有输入均为合成会话，运行于独立副本。草稿 PR 不合并；正式 DSH 配置、模型选择与凭据文件前后哈希一致。

## 修复与范围

旧版 `582457f` 中，“写入并回读校验”只存一个 write_file 目标时，成功写入即可错误标记 done；冻结旧版的中英文两个复现都得到 done，新版都保持 doing。

- 复合步骤用 `completion.all` 表示 2–6 个有序验收项，逐项要求同会话、最新匹配调用、独立成功回执及完整引用。
- `expect:{field,equals}` 可检查回执 JSON 顶层的标量值。成功读取不自动等于内容正确；缺字段待核验、值不符阻塞。
- 重新写入使此前回读失效；旧 done 也会纠正。模型返回 none 或请求失败时仍执行本地状态协调。
- 模型不能靠改名、删项或替换目标绕过旧验收；只能保持原顺序加强条件，加强当次仍须待复核。人工编辑保持原有优先级。
- 旧的单目标复合标题保守停在“验收项未拆分”；启发式只覆盖常见中英文连接词，不能理解任意自然语言验收。
- 敏感值/脱敏占位符不能成为验收身份，避免不同秘密被脱敏后误当成同一参数；新增回执事实仍经过脱敏和大小限制。

## 实验设计

16 个用例 × 2 次 × 3 组，共 **96 次真实 DeepSeek 请求**。当前 DSH 路由为 `deepseek-account / deepseek-flash`，服务返回名称 **DeepSeek-V4.1-Flash**，运行时 0.2.1-rc.5。沿用插件助手 reasoning Off（主 Agent 当前为 Max）；温度 0、输出上限 1000、单次截止 15 秒。官方 Q8 由现有 Ollama 提供，1024 维、8192 窗口。两次预实验用于修正计时口径及标题/验收弱化问题，未计入最终 96 次。

三组共用修复后的状态校验与相同事件、计划、提示构造、最近 24 条工具记录。关闭 RAG 仍有最近记录及状态校验，不是没有上下文。原策略为语义余弦加有限词法分；优化策略加入来源筛选、按目的的英文 query instruction、既有验收目标的最新回执定位及词法缓存。提升包含确定性目标查找的贡献，不能归因于 Q8 权重变强。

每个用例含 36 组相似助手声明及无关工具回执，将关键旧证据挤出最近窗口；另设最近成功回执对照。覆盖中文会话、英文思考、代码路径草图、约束、生成摘要、待返回、缺字段、错内容、重写后旧验证、失败、中断与无关操作。用例有意强调干扰和旧证据，不能代表普通生产会话的平均分布。

检索单测调用显式 purpose；实际计划管线统一用 mixed 加已有 completion，与 Host 接线一致。topK=5、检索正文预算 1800 字符（不含结构化元数据和独立约束账本）；索引先完成，再测冷/热查询各一次，三组顺序轮换。检索质量查询放在计划耗时测量之后，避免预热偏差。

## 结果

| 指标 | 关闭 RAG | 原 Q8 策略 hybrid | 优化 Q8 策略 typed |
|---|---:|---:|---:|
| 正确状态 / 32 | 30 | 30 | **32** |
| 未完成误标 done / 28 | 0 | 0 | **0** |
| 已完成漏标 / 4 | 2 | 2 | **0** |
| 校验前模型误提 done / 28 | 0 | 0 | 2（均拦截） |
| gold 记录宏平均 recall@5 / 30 次 | 不适用（关闭） | 26.7% | **100%** |
| 解析或请求错误 / 32 | 0 | 0 | 0 |
| 计划管线中位耗时 | 1197 ms | 1343 ms | **1324 ms** |
| 计划管线 p95 | 1567 ms | 1820 ms | **1640 ms** |
| 其中检索中位 / p95 | 0 / 0 ms | 14 / 34 ms | **13 / 34 ms** |

召回分母：15 个有 gold 的用例 × 2；“无关操作”没有 gold，不计召回。关闭组在原始数据以 0 编码，表中标不适用。11 个实际回执用例原策略召回均为 0，英文意图/约束/代码草图 4 个用例均为 1；优化组全部为 1。普通策略会检索到词面相似的助手陈述，不能视作执行证据。

关闭组和原策略各 2 次漏标都来自已被埋藏的成功写入+回读。最近回执对照三组均完成。优化组在“重新写入后沿用旧回读”两次请求中原始模型均提出 done，新校验均改为 doing/verification_stale，说明正确召回仍不能代替状态校验。

耗时是本地检索、计划提示构造、真实助手生成、解析及校验；**不是主 Agent 全程响应、UI 呈现或 1M token 请求延迟**，不含 700 ms 边界合并与首次建索引。每个合成用例建索引中位约 hybrid 1432 ms / typed 1410 ms；长会话首次索引未在本轮重测。32 次的 p95 使用 nearest-rank，差异很小，不能断言优化策略普遍更快。优化组相对关闭组中位多约 127 ms。

runner RSS 采样峰值约 **119.2 MiB**（三组共用进程），累计 CPU 约 2.55 秒；Ollama `/api/ps` 快照分配显存约 **2.66 GiB**。这不是每组独立的资源归因或整机峰值。

## 故障恢复

单独测试，未与 A/B 争用推理资源。临时 loopback 代理仅转发本机 Ollama，未关闭或改动原服务。

| 故障 | 观测结果 |
|---|---|
| HTTP 503 | 约 3.0 ms 回退词法，约束仍在，未误完成 |
| 无响应 | 约 263.8 ms 回退；250 ms 是向量等待预算，含评分的总耗时可略高 |
| 畸形维度 | 约 1.5 ms 拒绝并回退，未误完成 |
| 恢复正常 | 约 31.3 ms 恢复 hybrid 模式（typed 是策略名，hybrid 是本次传输/评分模式） |
| 冷索引连续失败 | 实际重试 3 次后停止；服务恢复并等待约 30.37 秒，下次查询重新建索引，无新增历史 |
| 真实 DeepSeek 中止 | 首个文本片段后取消，约 537.5 ms 结束；随后健康请求约 550.1 ms 成功 |

新增 Host 回归还模拟生成服务异常、模型 none、旧 done 恢复与后续真实回执到达；这里的服务异常是注入测试，不代表实测云端 429、区域断网或随机丢包。
